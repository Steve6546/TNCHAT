# TNCHAT — AI Command Center

بوابة توجيه للنماذج اللغوية (LLM gateway) مع لوحة تحكم عربية. تستقبل الطلبات
بصيغتي **OpenAI** و **Anthropic** وتوجّهها إلى أي مزوّد علوي، مع تحويل البروتوكول
في الاتجاهين، تدفّق SSE، إعادة المحاولة بين القنوات، وتسجيل الاستهلاك.

**قاعدة البيانات والحسابات في Supabase**: القنوات والمفاتيح والسجلات تُخزَّن في
Supabase Postgres، وحسابات لوحة التحكم (بريد إلكتروني + كلمة مرور + استرجاع
كلمة المرور بالبريد) في Supabase Auth. المشروع يعمل أونلاين فقط — اتصال
بالإنترنت مطلوب دائماً.

البوابة منقولة بأمانة عن [new-api](https://github.com/QuantumNous/new-api) مع
واجهة وإدارة حديثة. التغطية: **Claude ⇄ OpenAI** فقط — التحويل عبر Gemini
مُصنَّف `Discouraged` في المصفوفة الرسمية، فلم يُنفَّذ بدل ادّعاء الكمال.

## التشغيل — أمر واحد

```bash
node scripts/acc.mjs start
```

هذا كل شيء. الأمر ينفّذ بالتسلسل: يتحقق من إصدار Node ← يثبّت الاعتمادات ←
ينسخ `.env` من القالب ← يتحقق من إعدادات Supabase ← يطبّق مخطط قاعدة البيانات ←
يبني الخادم والواجة ← يشغّل كل شيء على **منفذ واحد**.

```
✔ AI Command Center is running
  dashboard + gateway  http://127.0.0.1:8787
```

افتح `http://127.0.0.1:8787`. أنشئ حساباً ببريدك الإلكتروني من شاشة «إنشاء
حساب» — وإن نسيت كلمة المرور فرابط الاسترجاع يصلك بالبريد عبر Supabase.

يعمل على Windows و macOS و Linux. مسار المجلد قد يحتوي مسافات أو `&` — المشغّل
لا يمرّر المسار عبر الصدفة أبداً.

### كل الأوامر

| الأمر | ما يفعله |
| --- | --- |
| `node scripts/acc.mjs start` | **الأمر الوحيد الذي تحتاجه**: تثبيت ← بناء ← تشغيل على منفذ واحد |
| `node scripts/acc.mjs dev` | تشغيل مع إعادة تحميل تلقائي (خادم + واجهة، عمليتان) |
| `node scripts/acc.mjs setup` | تثبيت الاعتمادات + إنشاء `.env` + تهيئة قاعدة البيانات |
| `node scripts/acc.mjs build` | فحص الأنواع ثم بناء الخادم والواجهة |
| `node scripts/acc.mjs test` | تشغيل مجموعة الاختبارات |
| `node scripts/acc.mjs check` | فحص الأنواع + الاختبارات — ما تشغّله CI |
| `node scripts/acc.mjs db` | تطبيق مخطط قاعدة البيانات على Supabase |
| `node scripts/acc.mjs reset` | حذف مفتاح التشفير المولَّد محلياً (يسأل أولاً) — بيانات Supabase لا تُمس |

مع تثبيت مدير حزم تعمل الاختصارات أيضاً: `pnpm start` · `pnpm dev` · `pnpm check`.

### المتطلبات

- **Node.js 22.5 أو أحدث**
- pnpm أو npm (يُكتشف تلقائياً، ويُثبَّت إن غاب)
- **مشروع Supabase** (مجاني): أنشئه من [supabase.com/dashboard](https://supabase.com/dashboard)،
  ثم انسخ من Project Settings القيم الثلاث إلى `.env` — انظر قسم الإعداد.
  الجلسات لا تنتهي تلقائياً: تنتهي بتسجيل الخروج أو بإغلاق المتصفح.


للبنية التفصيلية، ونظام التصميم، وخريطة ما نُقل من new-api:
**[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.

**لماذا منفذ واحد:** واجهة الإنتاج تُبنى إلى `web/dist` ويخدمها خادم البوابة
نفسه عبر `@fastify/static`. لا خادم ثانٍ، ولا بروكسي تطوير، ولا تعارض منافذ.
في وضع `dev` تعمل الواجهة على Vite مع إعادة تحميل تلقائي.

### مسار الطلب

```
عميل
 → TokenAuth          مفتاح العميل مُهشّأ sha256، يُتحقَّق من المجموعة والنماذج
 → AbilityIndex       (مجموعة، نموذج) ← قائمة قنوات مجهّزة مسبقاً   O(1)
 → Distributor        ارتباط ثابت → شرائح الأولوية → عشوائي موزون
 → ModelMapping       سلسلة إعادة توجيه مع كشف الدوران
 → Adaptor            بناء الرابط والترويسات
 → Convert            تحويل الجسم إلى صيغة المزوّد العلوي
 → Upstream           نداء + تدفّق SSE
 → Retry              عند الفشل: القناة التالية، وشريحة أولوية أقل
 → RequestLog         تسجيل الرموز والزمن والنتيجة
```

فهارس التوجيه تُبنى مرة واحدة في `rebuild()` ولا تُفرز ولا تُصفَّى لكل طلب.

## الاستخدام

أنشئ مفتاحاً من لوحة التحكم، ثم استخدمه مع أي مكتبة OpenAI أو Anthropic:

```bash
# بصيغة OpenAI
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"مرحباً"}]}'
```

```python
# بنفس المفتاح، عبر مكتبة Anthropic
import anthropic
client = anthropic.Anthropic(base_url="http://127.0.0.1:8787", api_key="sk-...")
print(client.messages.create(
    model="gpt-4o-mini", max_tokens=128,
    messages=[{"role": "user", "content": "مرحباً"}],
).content[0].text)
```

نفس القناة تخدم الصيغتين — التحويل يتم في البوابة.

### المسارات

| المسار | الوصف |
| --- | --- |
| `POST /v1/chat/completions` | بصيغة OpenAI، مع `stream: true` للتدفّق |
| `POST /v1/messages` | بصيغة Anthropic، مع `stream: true` للتدفّق |
| `GET /v1/models` | النماذج المتاحة لمجموعة المفتاح |
| `GET /health` | حالة الخادم وقاعدة البيانات وملخّص الإعداد |

مسارات الإدارة (`/api/*`) تتطلب جلسة لوحة التحكم.

## الإعداد

`.env` في جذر المشروع — **وهو المكان الوحيد الذي يُقرأ منه**. يُنسخ تلقائياً
من `.env.example` في أول تشغيل. قيم Supabase الثلاث **إلزامية**:

| المتغيّر | الافتراضي | ملاحظة |
| --- | --- | --- |
| `DATABASE_URL` | **إلزامي** | اتصال Postgres بمشروع Supabase — من Project Settings → Database |
| `SUPABASE_URL` | **إلزامي** | رابط المشروع — من Project Settings → API |
| `SUPABASE_ANON_KEY` | **إلزامي** | المفتاح العام للمشروع — من Project Settings → API |
| `HOST` / `PORT` | `127.0.0.1` / `8787` | |
| `MASTER_KEY` | يُولَّد ويُحفظ | يشفّر مفاتيح المزوّدين (AES-256-GCM). **انسخه احتياطياً في الإنتاج** |
| `SESSION_SECRET` | يُشتق من MASTER_KEY | يوقّع جلسات لوحة التحكم — منفصل عمّا يشفر البيانات |
| `CORS_ORIGIN` | `true` في التطوير | قائمة سماح بالإنتاج؛ لا يُقبل `*` أبداً |
| `TRUST_PROXY` | `false` | فعّله فقط خلف بروكسي موثوق يضبط `X-Forwarded-For` |
| `RETRY_TIMES` | `3` | عدد القنوات التي يُجرَّبها الطلب الفاشل |
| `REQUEST_TIMEOUT_MS` | `120000` | مهلة الطلب غير المتدفّق |
| `STREAMING_TIMEOUT_MS` | `300000` | مهلة الطلب المتدفّق |

راجع `.env.example` للقائمة الكاملة مع الشرح.

## الأمان

- **حسابات لوحة التحكم** تُدار بالكامل عبر Supabase Auth: كلمات المرور تُهشَّم
  لدى Supabase (bcrypt)، واسترجاع كلمة المرور يتم برسالة بريد من Supabase.
- **جلسة لوحة التحكم** رمز موقَّع HMAC بلا تاريخ انتهاء — تنتهي بتسجيل الخروج
  أو بإغلاق تبويب المتصفح (يُخزَّن في `sessionStorage`). لا عدّادات ولا
  انتهاء تلقائي.
- **مفاتيح المزوّدين** تُشفَّر AES-256-GCM قبل أن تلمس قاعدة البيانات، ولا تُعرض
  كاملة بعد إنشائها أبداً.
- **مفاتيح العملاء** تُخزَّن مُهشَّأة sha256. النص الصريح يظهر مرة واحدة فقط،
  في نافذة لا يمكن إغلاقها بالخطأ.
- **مفتاح الجلسة** مشتق عبر HKDF من `MASTER_KEY` بهدف توقيع الجلسة فقط —
  فلا يمكن تحويل جلسة مسرّبة إلى قدرة على فكّ تشفير المفاتيح المخزّنة.
- **تحديد المعدّل** على تسجيل الدخول وإنشاء الحساب والاسترجاع — المسارات الوحيدة
  المتاحة لتخمين بيانات الدخول.
- `.gitignore` يستثني `.env` والمفتاح الرئيسي. لا تدخل أي قيمة سرّية المستودع،
  ولا يُخزَّن أي مفتاح service_role لهذا المشروع على الجهاز.

## الاختبارات

```bash
node scripts/acc.mjs test    # التحويل بين الصيغ، الجلسات، pass-through، القناة المخصّصة
node scripts/acc.mjs check   # + فحص الأنواع
```

الاختبارات تغطّي أصعب ما في المشروع: تحويل الطلبات والردود والأحداث المتدفّقة
بين صيغتي OpenAI و Claude، ومرور طلبات Claude Code دون تعديل، ونوع القناة
المخصّص، وحلّ مسار النهاية تلقائياً عند الفحص. الاختبارات التي تلمس قاعدة
البيانات تعمل ضد `DATABASE_URL` المُعدَّ في `.env` وتمسح فقط الصفوف التي
أنشأتها بنفسها.
